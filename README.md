# Muse 网站界面学习项目

这是 [Muse · GPTibo](https://muse.gptibo.com/) 首页的独立界面复刻，用于学习 Next.js 页面实现。项目与 GPTibo 无关联。

**[打开在线预览](https://daolingz46-tech.github.io/muse-site-study/)**

在线预览支持输入测试信息、切换支付宝/微信支付、检查表单并演示确认流程。输入仅保存在当前页面的 React 内存中，不上传、不写入浏览器存储，刷新即清空；不创建真实订单，也不处理付款。网页顶部会明确标注这一点。

## 接入真实支付

当前只有前端演示，切换支付方式不会自动开通收款。正式接入前需要确定商户平台、产品权限、后端部署位置，以及自己的商店品牌和交付内容。GitHub Pages 只保留学习演示，正式交易站需部署到支持后端的环境。

1. 提供已开通的支付宝、微信商户平台或聚合支付平台名称及接口文档。私钥放在部署平台的服务端密钥配置中，不提交 Git、不使用 `NEXT_PUBLIC_` 变量。
2. 实现创建订单接口：前端提交商品、邮箱、支付方式；服务端读取商品价格和费用，以整数分计价，生成唯一订单号并存入数据库。
3. 服务端调用选定支付平台的下单接口，返回二维码或收银台链接；前端展示并查询订单状态。
4. 支付回调由服务端验签、核对商户/订单/金额，幂等更新支付结果。不能根据浏览器跳转就确认收款。
5. 支付成功后触发库存分配和邮件交付，记录交付状态并防止重复发货。订单查询验证查询凭据；增加限流、退款和对账处理。
6. 先完成平台测试环境或受控测试，再配置生产域名、HTTPS 和回调地址上线。

所需配置取决于最终选定的支付平台。目前没有写入商户密钥，也没有接通任何支付接口。页面中的价格与手续费仅是演示值。

## 本地运行

需要 Node.js 24 或更新版本。

```bash
npm ci
npm run dev
```

打开 http://localhost:3000/。提交前可运行 `npm run check`，它会执行 ESLint、TypeScript 和生产构建。

## 项目结构

- `src/components/sites/muse/`：页面组件和样式
- `public/sites/muse/`：页面使用的公开素材
- `docs/research/muse/`：原站与本地截图、观察记录
- `.github/workflows/deploy-pages.yml`：GitHub Pages 静态预览

本项目基于 [ai-website-cloner-template](https://github.com/JCodesMore/ai-website-cloner-template) 建立。原站的名称、标识和内容属于各自权利人。
